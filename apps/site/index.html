Features

Everything a careful team would do. Done for you, on every task.

01Spec

A spec before a single line of code

Tandem reads your repository, asks what it needs to know, and writes the spec in plain words: given, when, then. You approve that version, not a summary of it.

  • Your PM approves in Tandem, or by replying “approve” on the Jira issue
  • Ask for a change and the spec is drafted again, with approvals reset
  • Frontend and backend in separate repositories? One spec, linked pull requests

02Checks

Checks that really run, and tests that prove the spec

Every task runs your repository's own install, lint, type-check, build and test commands in a clean copy. When something fails, the agent gets the output and fixes it.

  • Each acceptance criterion is mapped to the test that proves it
  • Failures that were already on your main branch are told apart from new ones
  • Installed dependencies are shared between tasks, so checks start fast

03Pull request

A pull request your reviewers will actually read

Before you see it, a second pass reads the whole diff against the spec, the rules your team taught it and a security checklist, and fixes what matters. Then one commit, with a title a person would write.

  • The spec, the checks and every criterion's test in the description
  • When main moves on, Tandem keeps the branch mergeable, without force-pushing
  • Rules your team teaches it in review are followed on every task after

04Spend

Spend you can see coming

Copilot runs on your own plan. Pick the model for each task, see an estimate before it starts, and set limits that stop a task the moment it reaches them.

  • Daily and per-task limits, in prompts and in AI credits
  • Every model your Copilot plan offers, with its cost next to it
  • A task that hits a limit waits for you, with nothing half-pushed

Guardrails

Rules in code, not in a prompt.

What an agent may do is checked by Tandem before each action runs. The prompt repeats the rules, but nothing depends on the model following them.

Agents can

  • Read your repository, and edit files inside the task's own folder
  • Run your repository's own install, lint, type-check, build and test commands
  • Push to the feature/ branch Tandem made for the task

Agents can't

  • Merge, or push to your main branch or any branch they didn't create
  • Force-push. Only --force-with-lease, after Tandem's own rebase
  • Run cloud CLIs, curl, ssh, publish or deploy commands
  • Write outside the task folder, start before every approval, or pass your spend limits

FAQ

Questions, answered.

Anything else? Write to [privacy email].

Who merges the pull request?

A person, always. Tandem pushes only to the task's own branch and opens the pull request. Your review rules, CI and deploys stay exactly as they are.

Which Copilot plans work?

Copilot Free, Pro and Pro+, and Copilot Business or Enterprise from your company, on github.com or GitHub Enterprise Cloud (*.ghe.com). A workspace runs on one member's plan; your organisation may need to allow the Copilot CLI policy.

Which repositories and trackers?

GitHub and AWS CodeCommit repositories, in any language whose checks run from the command line. Jira Cloud connects with Atlassian's sign-in, Jira Data Center with a token. Without Jira, everything stays in Tandem.

What does a task cost?

The Copilot work counts against your own Copilot plan. Tandem shows an estimate in AI credits before a task starts, and stops it at the limits you set, per task and per day.

Where is our code processed?

In Tandem's cloud, in the EU: each task's code is cloned into its workspace's isolated folder for the build. With a company runner, it never leaves your computers. Copilot itself is processed by GitHub under your agreement with them.

Does Tandem train on our code?

No. Tandem trains no models. Your code is used only to do the task you asked for.

What if the checks fail?

The agent gets the output and two tries to fix it. If it still fails, the task waits and tells you why, in plain words, with what to do next. Failures already on your main branch are pointed out as such.

Can we run Tandem ourselves?

Yes. The same web app we host runs on your own server as one container, with your GitHub App. Or keep using ours and run only a company runner.
